# ออกแบบหน้าแรก --- Project Management Dashboard

## 1. เป้าหมาย

ออกแบบหน้าแรกสำหรับระบบจัดการและติดตามงานหรือโปรเจกต์ที่หัวหน้ามอบหมาย
ให้ผู้ใช้เห็นงานที่ยังไม่เสร็จ ความคืบหน้า กำหนดส่ง และกิจกรรมล่าสุดได้อย่างรวดเร็ว
โดยอ้างอิงภาพตัวอย่างที่แนบมา

## 2. แนวทางการออกแบบ

-   รูปแบบ: Modern, clean, professional dashboard
-   ภาษาในหน้าจอ: ภาษาไทย โดยคงคำศัพท์ทางเทคนิคที่จำเป็นเป็นภาษาอังกฤษ
-   เน้นความอ่านง่าย ใช้งานง่าย และแสดงข้อมูลสำคัญอย่างเป็นลำดับ
-   ใช้การ์ดมุมโค้ง เส้นขอบบาง และเงาอ่อน ๆ
-   รองรับการแสดงผลบนหน้าจอ Desktop และปรับตามขนาดหน้าจอได้

## 3. สีและตัวอักษร

-   **สีหลัก:** สีขาว สำหรับพื้นหลังและการ์ด
-   **สีรอง:** สีน้ำเงิน สำหรับเมนูที่เลือก ปุ่ม ลิงก์ และองค์ประกอบที่ต้องการเน้น
-   **สีตัวอักษรหลัก:** สีดำหรือกรมท่าเข้ม เมื่ออยู่บนพื้นหลังสีขาว
-   **ตัวอักษรบนพื้นหลังสีน้ำเงิน:** ใช้สีขาวเพื่อให้มีความคมชัดและอ่านง่าย
-   ใช้สีอื่นอย่างจำกัดเพื่อแยกสถานะงาน เช่น เขียวสำหรับเสร็จแล้ว ส้มสำหรับรอตรวจสอบ
    และแดงสำหรับงานเร่งด่วน
-   ตรวจสอบ contrast ของข้อความและพื้นหลังให้อ่านได้ชัดเจน

## 4. ไอคอน

-   ห้ามใช้ Emoji ใน UI
-   ใช้ไอคอนแบบเดียวกันทั้งระบบ เช่น Lucide Icons
-   ตัวอย่างไอคอน:
    -   หน้าหลัก: `House`
    -   โปรเจกต์: `Folder`
    -   งาน/รายการงาน: `ClipboardList`
    -   รายงาน: `ChartNoAxesColumn`
    -   ตั้งค่า: `Settings`
    -   เวลา: `Clock`
    -   ผู้ใช้: `UserRound`
    -   กำหนดส่ง: `CalendarDays`
    -   งานเสร็จแล้ว: `CircleCheck`
    -   งานที่ยังไม่เสร็จ: `CircleAlert`
    -   ความคืบหน้า: `ChartPie`
-   ใช้ไอคอนที่มีขนาดและน้ำหนักเส้นสม่ำเสมอ

## 5. โครงสร้างหน้า

### 5.1 Sidebar ด้านซ้าย

-   แสดงโลโก้และชื่อระบบ `Project Management`
-   เมนูหลัก:
    -   หน้าหลัก
    -   โปรเจกต์
    -   ตารางงาน
    -   รายงาน
    -   ตั้งค่า
-   เมนูที่กำลังใช้งานใช้พื้นหลังสีน้ำเงินและตัวอักษรสีขาว
-   เมนูปกติใช้พื้นหลังสีขาวและตัวอักษรสีเข้ม
-   บริเวณด้านล่างแสดงชื่อระบบ `Mecha Trainee`, คำอธิบาย
    `Project Management System` และเวอร์ชันระบบ

### 5.2 Header ด้านบน

-   ด้านซ้ายหรือส่วนเนื้อหาแสดงหัวข้อและคำทักทายผู้ใช้
-   ด้านขวาบนแสดง:
    -   เวลาและวันที่ พร้อมไอคอนนาฬิกา
    -   บัญชีผู้ใช้ พร้อมไอคอนผู้ใช้
    -   เมนูแบบ Dropdown สำหรับโปรไฟล์หรือออกจากระบบ
-   ไม่ใช้ Emoji ในคำทักทาย ให้ใช้ข้อความธรรมดาหรือไอคอนแทนเมื่อจำเป็น

### 5.3 แถบทักทาย

-   แสดงข้อความ เช่น `สวัสดี, Kittipat`
-   คำอธิบาย: `ตรวจสอบความคืบหน้าของงานและโปรเจกต์ที่ได้รับมอบหมายได้ที่นี่`
-   สามารถใช้พื้นหลังสีน้ำเงินได้ โดยข้อความทั้งหมดบนพื้นหลังต้องเป็นสีขาว
-   หากมีภาพประกอบ ควรเป็นภาพ UI/งานเอกสารที่เรียบง่าย ไม่ใช้ Emoji

### 5.4 การ์ดสรุปข้อมูล

แสดงการ์ดสรุปข้อมูลด้านบนของรายการงาน เช่น 1. โปรเจกต์ทั้งหมด 2. งานที่ยังไม่เสร็จ 3.
งานที่เสร็จแล้ว 4. งานใกล้ถึงกำหนดส่ง (เช่น ภายใน 7 วัน)

แต่ละการ์ดควรมีไอคอน ตัวเลข และคำอธิบายที่ชัดเจน ใช้สีพื้นหลังอ่อนที่เหมาะสม และไม่ใช้
Emoji

### 5.5 รายการงานที่ยังไม่เสร็จ

แสดงรายการงานที่ยังไม่เสร็จในรูปแบบการ์ดหรือตาราง โดยมีข้อมูล: -
ชื่องานหรือชื่อโปรเจกต์ - คำอธิบายสั้น ๆ - ประเภทงาน เช่น Frontend, Backend หรือ
Testing - กำหนดส่ง - สถานะงาน เช่น กำลังดำเนินการ, รอการตรวจสอบ, รอเริ่มทำ -
แถบความคืบหน้าและเปอร์เซ็นต์ - ปุ่มหรือลิงก์เพื่อเปิดดูรายละเอียดงาน

เรียงงานที่เร่งด่วนหรือใกล้ถึงกำหนดส่งไว้ก่อน และมีลิงก์ `ดูทั้งหมด`
เพื่อไปยังหน้ารายการงานเต็มรูปแบบ

### 5.6 แผงด้านขวา

แสดงข้อมูลเสริมเป็นการ์ดเรียงแนวตั้ง: - **ภาพรวมความคืบหน้า:** แสดงเปอร์เซ็นต์รวม
อาจใช้วงแหวน Progress และสรุปจำนวนงานตามสถานะ - **กิจกรรมล่าสุด:**
แสดงเหตุการณ์ล่าสุด เช่น มีงานใหม่ อัปเดตสถานะ หรือแก้ไขรายละเอียด พร้อมเวลา -
**โปรเจกต์ที่รับผิดชอบ:** แสดงชื่อโปรเจกต์ สถานะ และจำนวนงานที่ยังไม่เสร็จ
พร้อมทางลัดไปยังรายละเอียด

## 6. ข้อกำหนดสำคัญ

-   **นำปฏิทินออกจากหน้าแรกทั้งหมด** ไม่ต้องแสดง Calendar widget หรือปฏิทินรายเดือน
-   สามารถแสดงกำหนดส่งเป็นวันที่ในรายการงานได้ โดยไม่ต้องมีปฏิทิน
-   ห้ามใช้ Emoji ในเมนู การ์ด ป้ายสถานะ หรือข้อความ UI ให้ใช้ไอคอนแทน
-   ถ้าพื้นหลังเป็นสีน้ำเงิน ตัวอักษรต้องเป็นสีขาว
-   ถ้าพื้นหลังเป็นสีขาวหรือสีอ่อน ตัวอักษรหลักต้องเป็นสีดำหรือกรมท่าเข้ม
-   ใช้สีขาวเป็นสีหลักและสีน้ำเงินเป็นสีรอง
-   อย่าเปลี่ยนแปลง Backend หรือ API โดยไม่ได้รับอนุญาต
-   หากเชื่อมต่อข้อมูลจริงไม่ได้ ให้แสดงสถานะหรือข้อความแจ้งเตือนที่เหมาะสม
    โดยไม่ทำให้หน้า Dashboard พัง

## 7. แนวทางการพัฒนา Frontend

-   ทำงานตามโครงสร้างโปรเจกต์เดิมและใช้เทคโนโลยีที่มีอยู่แล้ว
-   แยกส่วนประกอบตามหน้าที่ เช่น `Sidebar`, `Header`, `SummaryCard`,
    `TaskList`, `ProgressOverview`, `RecentActivity` และ
    `AssignedProjects`
-   ใช้ข้อมูลจาก API เดิมเมื่อมีอยู่แล้ว ไม่สร้าง API หรือแก้ Backend เอง
-   จัดการสถานะ Loading, Error และกรณีไม่มีงาน
-   ทำให้เมนู ปุ่ม `ดูทั้งหมด` และรายการงานนำทางไปยังหน้าที่ถูกต้อง
-   ตรวจสอบ Responsive layout และการอ่านข้อมูลบนหน้าจอขนาดเล็ก

## 8. เกณฑ์ตรวจรับ

-   หน้าแรกมี Sidebar, Header, การ์ดสรุป, รายการงานที่ยังไม่เสร็จ
    และแผงข้อมูลด้านขวา
-   เวลาและบัญชีผู้ใช้แสดงอยู่บริเวณขวาบน
-   ไม่มีปฏิทินบนหน้าแรก
-   ไม่มี Emoji ใน UI และใช้ไอคอนแทน
-   สีหลักเป็นสีขาว สีรองเป็นสีน้ำเงิน และข้อความบนพื้นหลังสีน้ำเงินเป็นสีขาว
-   งานที่ยังไม่เสร็จแสดงสถานะ กำหนดส่ง และความคืบหน้าอย่างชัดเจน
-   ไม่แก้ไข Backend โดยไม่ได้รับอนุญาต
